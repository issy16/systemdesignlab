    The one difference
    The bug lives in the gap between checking (“is there a seat?”) and changing (“take it”). Anything can happen in that gap. Fix it by making check-and-change one atomic step (a conditional UPDATE), or by locking the row so nobody else can enter the gap.
    
  
    Race condition in one line
    A race condition is a bug that appears only when operations overlap in an unlucky order. Each piece is correct on its own, and the result depends on timing.

    The bug
    Check, then act
    Read a value, decide, write based on what you read. Correct alone, wrong when two run at once. Tests that run one request at a time never see it.
    
    
    Fix 1
    Atomic update
    Put the check inside the write: UPDATE … WHERE seats_left > 0. The database does both in one step.
    
    
    Fix 2
    Lock
    SELECT … FOR UPDATE or a mutex: one at a time through the gap. Simple to reason about, but others wait (page 13).
    
  
    
  
    The tradeoff
    Atomic updates are fast but only work when the whole decision fits in one statement. Locks handle any logic, but they make others wait and can deadlock. Prefer atomic operations and database constraints, and reach for locks when the logic can't be expressed that way.
