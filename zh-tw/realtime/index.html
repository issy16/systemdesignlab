試試看

    一問再問
    輪詢（Polling）

    瀏覽器每隔幾秒問一次。簡單、到處都能用，但更新要等下一次輪詢，而大部分的回答都是「沒有新消息」。

    問了就等
    長輪詢（Long polling）

    瀏覽器發問，伺服器把請求保持開啟，直到有新消息才回應，接著瀏覽器再問一次。幾乎即時，用的是一般的 HTTP。

    伺服器說話
    伺服器推送事件（SSE）

    一個永遠不結束的 HTTP 回應；事件發生時，伺服器就把它寫進去。只有伺服器 → 瀏覽器，而且會自動重新連線。

    雙方都說話
    WebSocket

    一條升級成雙向通道的 HTTP 連線。任何一方隨時都能傳送。最適合聊天、遊戲和協作。

    關鍵差別

    重點在於誰能發起訊息。輪詢時只有瀏覽器能發起，所以新消息要等下一次發問。長輪詢和 SSE 讓伺服器在事情發生的那一刻就能回應，但只有一個方向。WebSocket 讓雙方隨時都能傳送。選擇能涵蓋你流量方向的最簡單方案。

    伺服器 → 瀏覽器，簡單版
    SSE
    即時動態、通知、進度、座位圖。一般的 HTTP、自動重新連線，也能搭配 HTTP/2。
    
    
    雙向
    WebSocket
    聊天、多人遊戲、協作編輯：任何瀏覽器也需要經常傳送的情境。
    
    
    後備方案
    長輪詢（Long polling）
    能穿過最嚴格的代理伺服器。比較慢、比較重，但幾乎不會被擋。
    
  
    
  
    取捨
    開著的連線不是免費的：10,000 位歌迷就代表你的伺服器和負載平衡器要撐住 10,000 條連線，部署時還要小心處理（重新連線風暴）。輪詢很浪費，但它是無狀態的，容易擴展。在新鮮度很重要時用推送，可以晚幾秒的東西就繼續用輪詢。
