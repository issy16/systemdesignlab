TCP 與 UDP

試試看

    TCP

    一條有交握、確認、重送與排序的連線。App 拿到的是一串完美的位元組。封包遺失時，後面的一切都要等待（隊頭阻塞，head-of-line blocking）。

    UDP

    送出就不管的封包：沒有交握、不重試、不排序。遺失的就遺失了，晚到的也不會等。由 App 自己決定怎麼處理，在舊資料毫無價值時非常好用。

    關鍵差別

    TCP 會等到拿齊所有依序的位元組；UDP 則把此刻已經到達的東西交出去。檔案、網頁和付款要用 TCP。直播視訊、語音和遊戲中，晚到的封包跟遺失的一樣糟，所以 UDP（由 App 自己補洞）勝出。

    完整＋有序
    TCP
    交握、確認、重送、排序、壅塞控制。HTTP/1 和 HTTP/2、資料庫、SSH 和 email 都使用它。
    
    
    快速＋會掉
    UDP
    就只是封包。DNS、視訊通話、遊戲和直播都使用它，QUIC 也是：它在 UDP 之上建立自己的可靠機制（第 23 頁）。
    
    
    代價
    隊頭阻塞
    一個遺失的 TCP 封包會拖延它後面的所有東西，連已經到達的資料也一樣。
    
  
    
  
    取捨
    TCP 免費給你正確性，代價是網路差時的延遲。UDP 給你低延遲，但要你自己處理遺失、排序和壅塞。這就是為什麼大多數 App 用 TCP，而需要即時性的 App 則在 UDP 之上加自己的協定。
