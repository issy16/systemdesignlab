試試看

    背壓（Backpressure）

    當消費者跟不上時，系統會叫生產者放慢速度（拒絕、等待或稍後重試），而不是無止盡地緩衝。沒有上限的佇列，只會把「慢」變成「記憶體不足」。

    死信佇列

    一再失敗的訊息（毒藥訊息，poison message）在試過幾次後會被移到一旁，不再卡住工作者。之後由人或工具來檢查死信佇列。

    關鍵差別

    沒有佇列時，歌迷要等最慢的那一步。有了佇列，歌迷只要等此刻真正重要的步驟，其他的稍後補上。佇列能吸收尖峰，但前提是它的大小有上限，而且失敗的訊息有地方去。

    解耦
    訊息佇列
    生產者丟出訊息，工作者稍後處理。回應快速，尖峰被吸收而不是被往下傳。
    
    
    放慢
    背壓（Backpressure）
    限制佇列大小，滿了就把壓力推回給生產者。有上限，好過記憶體不足。
    
    
    擱置
    死信佇列
    失敗 N 次後把訊息移開，這樣一則壞訊息就不會永遠佔住一個工作者。
    
  
    
  
    取捨
    佇列讓工作最終會完成，而不是現在完成。這非常適合 email、PDF 和分析資料，但歌迷的座位仍然必須在結帳時保留。盯著佇列的長度和年齡：它們是你的早期警訊。
