試試看

    關鍵差別

    DNS 變更並不會「傳播」：每個快取只是保留舊答案，直到它的 TTL 到期。TTL 長，查詢次數少、頁面更快，但變更很慢。在計畫好的搬遷前一天先調低 TTL（讓舊的長 TTL 副本先過期），然後切換，之後再調回來。

    一句話說清楚 DNS

    DNS 透過詢問一連串的伺服器（根伺服器 → 頂級網域 → 該網域自己的伺服器）把名稱轉成位址，而每個答案在沿途都會依 TTL 的長度被快取。

    一條鏈
    解析
    瀏覽器 → 作業系統 → 遞迴解析器 → 根伺服器 → 頂級網域 → 權威伺服器。只有冷查詢才會走完整條鏈。
    
    
    快取
    TTL
    每個答案都帶著 TTL。每一層都會快取那麼久，這就是為什麼大多數查詢只要 0 毫秒，也是為什麼變更很慢。
    
    
    記錄
    A, CNAME, MX…
    A：名稱 → IPv4 位址。AAAA：IPv6。CNAME：另一個名稱的別名。MX：email 要送去哪裡。TXT：驗證與政策。
    
  
    
  
    取捨
    TTL 長能減少查詢流量和延遲，但讓變更和故障轉移變慢；TTL 短讓變更很快，但會增加 DNS 伺服器的負擔。很少變動的記錄用小時，緊急時可能需要搬移的記錄用分鐘。
