樂觀鎖（Optimistic locking）
假設衝突很少見。不擋任何人，而是在儲存時檢查資料有沒有被改過（一個版本號碼）。如果改過，就拒絕這次儲存，讓使用者重試。衝突少的時候成本很低。

    
悲觀鎖（Pessimistic locking）
假設衝突一定會發生。在編輯前先鎖住資料，讓其他人排隊等。不會有被拒絕的儲存，但大家要等，而且忘記釋放的鎖會擋住所有人。

    關鍵差別
    死結（deadlock）需要一個循環：A 握著 B 要的東西，同時 B 握著 A 要的東西。資料庫會偵測到循環，並終止其中一個交易。預防的方法是讓每個交易都以同樣的順序取得鎖（例如 id 小的先鎖）。這樣第二個交易只會等待，而不會去搶另一把鎖。

    儲存時檢查
    樂觀鎖
    一個版本欄位。UPDATE … WHERE version = 1；影響 0 列代表別人先儲存了。最適合衝突很少的情況。
    
    
    先上鎖
    悲觀鎖
    在交易中使用 SELECT … FOR UPDATE。其他人要等。最適合短暫、競爭激烈的操作，例如座位庫存。
    
    
    永遠等待
    死結
    兩個交易各自握著對方需要的鎖。用一致的鎖定順序和短交易來預防；資料庫終止其中一個時就重試。
    
  
    
  
    取捨
    樂觀鎖從不阻擋，但會把衝突丟回給使用者或重試程式。悲觀鎖讓人等待來避免衝突，而你取得的每一把鎖都是一次死結的機會。大多數網頁應用程式對編輯表單用樂觀鎖，對熱門計數器用短暫的悲觀鎖。
