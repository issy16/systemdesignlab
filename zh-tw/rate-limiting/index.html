令牌桶（token bucket）

每個桶子最多裝 B 個令牌，每秒補充 R 個。每個請求花掉一個令牌。沒有令牌，請求就會立刻被 429 Too Many Requests 拒絕，伺服器完全不用做那份工作。數字是模擬的。

    關鍵差別

    單一共用限額能保護伺服器，卻讓所有人一起為機器人的行為受罰。每位使用者各自的限額（依帳號、API 金鑰或 IP）既能保護伺服器，又能讓機器人的行為只影響機器人自己。

    一句話說清楚限流

    限制每個客戶端在一段時間內能發出的請求數，並在多出來的請求耗費真正的工作之前，用 429 便宜地拒絕它們。桶子大小允許短暫的突發；補充速率決定長期的上限。

    是什麼
    限流
    限制每個客戶端在每段時間內的請求數。多出來的請求會很快拿到 429，而不是耗掉伺服器容量。
    
    
    怎麼做
    令牌桶
    桶子大小＝允許多大的突發。補充速率＝持續的上限。簡單、便宜，也是最常見的演算法。
    
    
    針對誰
    每個客戶端各自計算
    依使用者、API 金鑰或 IP 建立桶子，這樣一個重度客戶端就不能用光所有人的額度。
    
  
    
  
    取捨
    限額太緊，會在最忙的那一刻擋掉真正的歌迷；限額太鬆，什麼都保護不了。允許合理的突發、依客戶端限流，並告訴客戶端什麼時候可以再來（Retry-After）。
