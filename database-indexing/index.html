    Indexing in one line

    Without an index the database must read every row to be sure it found all matches. An index is a sorted lookup structure (usually a B-tree) that jumps straight to the matching rows.

    act 2 · query optimization26

    Having an index isn't enough. The query has to be able to use it.

    The index stores emails sorted exactly as written. Pick a query and see whether the database can still use it.

    The one difference
    An index helps only when the database can search the column the same way it's sorted. Wrapping the column in a function, or starting a search with a wildcard, sends it back to reading every row.

    So why not index every column?

    The whole page on one screen
    
  
    
    
    Without
    Full scan
    The database reads every row. The cost grows with the table, so the same query gets slower every month.
    
    
    With
    Index
    A sorted tree on the column. A lookup reads a handful of pages, whether the table has a thousand rows or a billion.
    
    
    Check
    EXPLAIN
    Never guess. EXPLAIN ANALYZE tells you whether the index was used and how many rows were read.
    
  
    
  
    The tradeoff
    Indexes make reads fast and writes slower, and they take space. Index the columns your important queries filter or sort by, not every column.
