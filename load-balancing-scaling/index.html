    Scale up (vertical)

    One bigger machine. No code changes and nothing to coordinate. But there's a largest machine you can buy, upgrading usually means downtime, and when it dies, everything dies with it.

    Scale out (horizontal)

    More machines behind a load balancer. Grows almost without limit and survives losing a machine. But the app must not keep important state in one server's memory, since the next request may land elsewhere.

    The one difference

    Scaling up makes one server stronger. Scaling out adds servers and needs a load balancer to split the traffic. How it splits matters: least connections notices a server stuck on slow requests, while round robin keeps sending it more.

    Stronger
    Vertical scaling
    A bigger machine. Easiest first step, with a hard ceiling and a single point of failure.
    
    
    More
    Horizontal scaling
    More machines. Survives failures and keeps growing, as long as servers are interchangeable (stateless).
    
    
    Traffic cop
    Load balancer
    Splits requests across servers, skips dead ones, and picks a strategy: round robin, least connections, and others.
    
  
    
  
    The tradeoff
    Scaling up is simple until it isn't. Scaling out costs some design work (shared sessions, a shared database) but removes the ceiling and the single point of failure. Most teams start up and move out.
