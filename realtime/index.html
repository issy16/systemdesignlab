    Ask again and again
    Polling

    The browser asks every few seconds. Simple and works everywhere, but updates wait for the next poll, and most answers are “nothing new”.

    Ask and wait
    Long polling

    The browser asks, and the server holds the request open until there's news, then the browser asks again. Near-instant, with plain HTTP.

    Server talks
    Server-Sent Events

    One HTTP response that never ends; the server writes events into it as they happen. Server → browser only, reconnects automatically.

    Both talk
    WebSocket

    An HTTP connection upgraded into a two-way channel. Either side can send at any time. Best for chat, games and collaboration.

    The one difference

    It's about who can start a message. With polling, only the browser does, so news waits for the next question. Long polling and SSE let the server answer the moment something happens, in one direction. A WebSocket lets both sides send whenever they want. Pick the simplest one that covers your direction of traffic.

    WebSocket
    Chat, multiplayer, collaborative editing: anything where the browser sends often too.

    Long polling
    Works through the strictest proxies. Slower and heavier, but almost never blocked.
    
  
    
  
    The tradeoff
    Open connections aren't free: 10,000 fans means 10,000 connections held by your servers and load balancers, and they need care during deploys (reconnect storms). Polling is wasteful but stateless and easy to scale. Use push when freshness matters, and keep polling for things that can be a few seconds old.
