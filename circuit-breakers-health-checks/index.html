    The one difference

    Without a breaker, every request keeps calling a dependency that's known to be broken, and waits the full timeout each time. A circuit breaker counts failures. After a few in a row it opens: calls are skipped instantly and a fallback is used. After a cooldown it lets one test call through, and closes again if that works.

    Three instances, two kinds of “are you OK?”

    The load balancer sends traffic to three copies of Encore's API. api-2 just started and is still loading its cache. api-3 is stuck in a deadlock: the process is running, but it never answers. Pick which checks the platform runs, then move time forward.

    t = 0 s

    Liveness probe

    “Is this process stuck?” If it fails several times, restart it. That fixes deadlocks and hangs.

    Readiness probe

    “Can it take traffic right now?” If not, stop sending it requests, but don't restart it. For startup, warm-up, or a lost database connection.

    The tradeoff
    A breaker turns a slow failure into a fast, partial one: fans get the page without recommendations. That only works if you design a fallback. Thresholds that are too sensitive open on small blips; too lax, and they open after the damage is done.
