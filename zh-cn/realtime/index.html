    一问再问
    轮询（Polling）

    浏览器每隔几秒问一次。简单、到处都能用，但更新要等下一次轮询，而大部分的回答都是「没有新消息」。

    问了就等
    长轮询（Long polling）

    浏览器发问，服务器把请求保持打开，直到有新消息才响应，接着浏览器再问一次。几乎实时，用的是一般的 HTTP。

    服务器说话
    服务器推送事件（SSE）

    一个永远不结束的 HTTP 响应；事件发生时，服务器就把它写进去。只有服务器 → 浏览器，而且会自动重新连接。

    双方都说话
    WebSocket

    一条升级成双向通道的 HTTP 连接。任何一方随时都能发送。最适合聊天、游戏和协作。

    关键差别

    重点在于谁能发起消息。轮询时只有浏览器能发起，所以新消息要等下一次发问。长轮询和 SSE 让服务器在事情发生的那一刻就能响应，但只有一个方向。WebSocket 让双方随时都能发送。选择能涵盖你流量方向的最简单方案。

    后备方案
    长轮询（Long polling）
    能穿过最严格的代理服务器。比较慢、比较重，但几乎不会被挡。
    
  
    
  
    取舍
    开着的连接不是免费的：10,000 位歌迷就代表你的服务器和负载平衡器要撑住 10,000 条连接，部署时还要小心处理（重新连接风暴）。轮询很浪费，但它是无状态的，容易扩展。在新鲜度很重要时用推送，可以晚几秒的东西就继续用轮询。
