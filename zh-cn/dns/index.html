    关键差别

    DNS 变更并不会「传播」：每个缓存只是保留旧答案，直到它的 TTL 到期。TTL 长，查找次数少、页面更快，但变更很慢。在计划好的搬迁前一天先调低 TTL（让旧的长 TTL 副本先过期），然后切换，之后再调回来。

    一句话说清楚 DNS

    DNS 通过询问一连串的服务器（根服务器 → 顶级网域 → 该网域自己的服务器）把名称转成地址，而每个答案在沿途都会依 TTL 的长度被缓存。

    一条链
    解析
    浏览器 → 操作系统 → 递归解析器 → 根服务器 → 顶级网域 → 权威服务器。只有冷查找才会走完整条链。
    
    
    缓存
    TTL
    每个答案都带着 TTL。每一层都会缓存那么久，这就是为什么大多数查找只要 0 毫秒，也是为什么变更很慢。
    
    
    记录
    A, CNAME, MX…
    A：名称 → IPv4 地址。AAAA：IPv6。CNAME：另一个名称的别名。MX：email 要送去哪里。TXT：验证与政策。
    
  
    
  
    取舍
    TTL 长能减少查找流量和延迟，但让变更和故障转移变慢；TTL 短让变更很快，但会增加 DNS 服务器的负担。很少变动的记录用小时，紧急时可能需要搬移的记录用分钟。
