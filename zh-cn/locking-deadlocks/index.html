乐观锁（Optimistic locking）
假设冲突很少见。不挡任何人，而是在保存时检查数据有没有被改过（一个版本号码）。如果改过，就拒绝这次保存，让用户重试。冲突少的时候成本很低。

    
悲观锁（Pessimistic locking）
假设冲突一定会发生。在编辑前先锁住数据，让其他人排队等。不会有被拒绝的保存，但大家要等，而且忘记释放的锁会挡住所有人。

    关键差别
    死结（deadlock）需要一个循环：A 握着 B 要的东西，同时 B 握着 A 要的东西。数据库会侦测到循环，并终止其中一个交易。预防的方法是让每个交易都以同样的顺序取得锁（例如 id 小的先锁）。这样第二个交易只会等待，而不会去抢另一把锁。

    保存时检查
    乐观锁
    一个版本字段。UPDATE … WHERE version = 1；影响 0 列代表别人先保存了。最适合冲突很少的情况。
    
    
    先上锁
    悲观锁
    在交易中使用 SELECT … FOR UPDATE。其他人要等。最适合短暂、竞争激烈的操作，例如座位库存。
    
    
    永远等待
    死结
    两个交易各自握着对方需要的锁。用一致的锁定顺序和短交易来预防；数据库终止其中一个时就重试。
    
  
    
  
    取舍
    乐观锁从不阻挡，但会把冲突丢回给用户或重试程序。悲观锁让人等待来避免冲突，而你取得的每一把锁都是一次死结的机会。大多数网页应用程序对编辑表单用乐观锁，对热门计数器用短暂的悲观锁。
