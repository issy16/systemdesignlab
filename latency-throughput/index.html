One server, rising traffic

Each request is a fan loading a page, and fans arrive in bursts, like real traffic. The server works on 2 requests at a time, and each needs about 20 ms of work. That comes out to roughly 100 requests per second (simulated numbers, not a benchmark). Every response also spends 40 ms on the network. Requests that arrive while both workers are busy wait in line.

    Latency vs throughput in one line

    Latency is how long one request takes. Throughput is how many requests finish per second. Near a server's limit, throughput stops rising and latency shoots up.

    The one difference

    The average blends everyone into one number that describes nobody. P99 is the time the slowest 1% of users waited. Those are the fans writing to support.

    act 3 · tail latency multipliesfan-out

    One page, many calls

    Encore's concert page doesn't make one request. It calls the seat map, prices, recommendations, reviews… Each call is slow only 1% of the time. But the page is slow if any of its calls is slow.

    Tail latency

    The rare slow requests at the end of the distribution are the tail. With fan-out, rare per call becomes common per page, so big systems watch P99 and even P99.9.

    The tradeoff
    Running a server closer to 100% busy gets more throughput per dollar, but latency explodes near the limit. Leave headroom, and judge speed by P99, not the average.
