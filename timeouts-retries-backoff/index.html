Try this

    Timeout

    How long you wait before giving up on one call. With no timeout, a slow dependency makes every request wait with it, and your own servers run out of threads.

    Retry

    Trying again after a failure. It fixes brief, random errors. But every retry is extra load, sent at the exact moment the other side is struggling.

    The one difference

    Retrying immediately makes every client retry at the same moment, so failures come back as bigger waves. Exponential backoff waits longer after each failure (1 s, 2 s, 4 s…), and jitter adds randomness so clients spread out instead of retrying in sync.

    Stop waiting
    Timeout
    Every network call gets a deadline. Without one, a slow dependency freezes your whole service.
    
    
    Try again
    Retry
    Retry only errors that might go away (timeouts, 503, 429), a limited number of times, and only for requests that are safe to repeat.
    
    
    Spread out
    Backoff + jitter
    Wait longer after each failure, with a random part, so retries don't arrive as one synchronized wave.
    
  
    
  
    The tradeoff
    Retries trade extra load for a better chance of success. Short timeouts and many retries fail fast but multiply traffic; long timeouts and few retries are gentle but slow. Cap retries, back off with jitter, and retry only requests that are safe to repeat (page 10).
