    TLS (encryption in transit)
    Encrypts data between two machines and proves the server is who it claims to be, using a certificate signed by an authority the browser trusts. Use it everywhere data travels: browser to site, and service to service.
    
    
    Secrets management
    Keys, passwords and tokens live in a secret store (or environment variables injected at deploy time), never in code or git. Every secret can be rotated: replaced with a new one while the old one is revoked.
    
  
    
  
    The one difference
    Encryption only helps if the key stays secret. TLS keeps attackers from reading data in transit; a leaked key lets them walk in through the front door. Once a secret has been exposed, deleting it doesn't un-expose it. You must rotate it.

    Private + authentic
    TLS
    Encrypts the connection and verifies the server's certificate. The attacker sees where you connect, not what you send.
    
    
    Everywhere
    Encryption in transit
    Not just the browser: databases, queues and internal APIs too. Networks inside a data center aren't automatically safe.
    
    
    Out of the code
    Secrets management
    Store secrets in a secret manager, give each service only what it needs, and rotate on any leak.
    
  
    
  
    The tradeoff
    TLS costs a little setup and almost nothing in speed today, so there's no reason to skip it. Secret managers add a dependency and some process, but a single leaked key can cost far more. Automate certificate renewal and secret rotation so they don't depend on someone remembering.
